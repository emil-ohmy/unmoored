# MyGame

**The Ferryman's Apprentice.** Design brief: `docs/brief.md`. Glossary (use these terms): `CONTEXT.md`.
Decision history: `.scratch/game-brief/` (wayfinder map + tickets).

3D game: Unity 6.6 (6000.6.3f1, URP) + Blender 5.2 for models. Driven mostly from the CLI.

## Layout

```
art/models/<category>/<name>.py   one script per model (built with tools/blender/kit.py); the .blend is generated
  characters/                     rigged + animated (apprentice, laden)
  environment/                    static; get mesh colliders on import (quay, jetty, houses, props...)
art/prototypes/                   throwaway prototype sources (see branches prototype/*)
tools/
  build-models.sh [names]         .py -> .blend + FBX into game/Assets/_Project/Art/Models/<Category>/
  preview-poses.sh <name>         contact sheet of a rig's animations (builds/poses-<name>.png)
  blender/kit.py                  modelling, rigging (poses in armature space), FBX export helpers
  unity.sh                        open | import | build-mac | build-webgl | test
game/Assets/_Project/
  Art/Models/                     generated FBX (never edit; rebuild from art/models)
  Art/Shaders/                    Toon (outline, stepped light, lantern light), Water (waves, foam)
  Art/Generated/                  assets the scene builder creates (water mesh, materials, volume)
  Scenes/Main.unity               generated by MainSceneBuilder (Assets > MyGame > Build Main Scene)
  Scripts/Runtime/                game code, assembly MyGame.Runtime (namespace MyGame)
  Scripts/Editor/                 ModelImportRules, MainSceneBuilder, BuildScript
  Tests/PlayMode/                 MainSceneTests (rules from the brief), PlayCaptureTests (screenshots)
```

## Workflow

- Models are code: edit `art/models/**/<name>.py`, run `tools/build-models.sh <name>`. Never hand-edit the FBX
  in `game/`. Front is -Y in Blender; the export makes it Unity's forward (+Z), so
  `transform.forward` is where a character looks. 1 unit = 1 m, origin at the base.
- Rig poses: `kit.animate` takes rotations in degrees about world axes around the bone head (+X leans an upright
  bone forward). From the game camera a forward-tipped prop foreshortens and reads as "down": check poses with
  `tools/preview-poses.sh` before importing.
- Import rules (`ModelImportRules`): Blender material colours become `MyGame/Toon` materials; names ending in
  `_Glow` become emissive; smoothed normals are baked into tangents for the outline. Rigged FBX skip Blender's
  bake_space_transform (broken with armatures) and use Unity's bakeAxisConversion, so their roots keep a
  rotation: compose yaw with the prefab's root rotation when placing.
- The Main scene is generated: change the layout in `MainSceneBuilder`, not in the editor.
- Tests: `tools/unity.sh test` (EditMode + PlayMode). MainSceneTests drive the Apprentice through
  `ScriptedInput`. For screenshots of play: `SHOTS=<dir>` + `-testFilter PlayCaptureTests`.
- Headless Unity commands fail if the editor has the project open. Then work in a copy
  (rsync without Library/), rebuild the scene there, and let the user run the menu item in the real project;
  never copy generated scenes/assets back (their GUIDs differ).
- Unity logs from the CLI end up in `builds/unity-<command>.log`.
- Tuning lives on the components (Apprentice, Laden) with the brief's "Middle" values as defaults.
- Version control: git + LFS. Binaries (.blend, .fbx, images, audio, fonts) go through LFS via
  `.gitattributes`; add new binary extensions there before committing them.
