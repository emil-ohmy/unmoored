# MyGame

**The Ferryman's Apprentice.** Design brief: `docs/brief.md`. Glossary (use these terms): `CONTEXT.md`.
Decision history: `.scratch/game-brief/` (wayfinder map + tickets).

3D game: Unity 6.6 (6000.6.3f1, URP) + Blender 5.2 for models. Driven mostly from the CLI.

## Workflow

- Models are code: edit `art/models/**/<name>.py`, run `tools/build-models.sh <name>`. Never hand-edit the FBX
  in `game/`. Front is -Y in Blender; the export makes it Unity's forward (+Z), so
  `transform.forward` is where a character looks. 1 unit = 1 m, origin at the base. Static (environment) models
  keep a 180° root rotation from the import, so their `transform.forward` is their visual *back*: aim props by
  position (or `-forward`), not by `forward`.
- Rig poses: `kit.animate` takes rotations in degrees about world axes around the bone head (+X leans an upright
  bone forward). From the game camera a forward-tipped prop foreshortens and reads as "down": check poses with
  `tools/preview-poses.sh` before importing.
- Import rules (`ModelImportRules`): Blender material colours become `MyGame/Toon` materials; names ending in
  `_Glow` become emissive, and in `_Metal` metal (a hard glint from the moon and lanterns); smoothed normals are baked into tangents for the outline. Rigged FBX skip Blender's
  bake_space_transform (broken with armatures) and use Unity's bakeAxisConversion, so their roots keep a
  rotation: compose yaw with the prefab's root rotation when placing.
- Sounds are code too: `art/audio/<name>.py` defines render(variant, rng) (+ VARIANTS, LOOP). The list of every
  sound and its source (synth / AI / library) is `art/audio/sounds.md`. Claude can't listen: check shape with a
  spectrogram (`ffmpeg ... showspectrumpic`) and look for clicks (layers cut before they decay), then the user
  judges by ear. `Sfx` plays one-shots with variant/pitch/volume variation; the AudioListener follows the
  Apprentice (not the camera).
- The Main scene is generated: change the layout in `MainSceneBuilder`, not in the editor.
- Tests: `tools/unity.sh test` (EditMode + PlayMode, a few seconds; skips `[Category("Slow")]` measurements) and
  `tools/unity.sh test-all` (everything, before a merge). MainSceneTests drive the Apprentice through `ScriptedInput`
  and step time at a fixed 1/60 s (`Time.captureDeltaTime`), so they're deterministic and run far faster than the
  game time they cover: wait in game time (`WaitForSeconds`, `Time.deltaTime`), never real time. For screenshots
  of play: `SHOTS=<dir>` + `-testFilter PlayCaptureTests`. A test that needs a long measurement gets `[Category("Slow")]`.
- Headless Unity commands fail if the editor has the project open. Then work in a copy
  (rsync without Library/), ALWAYS rebuild the scene there after every sync (synced .meta files can change script
  GUIDs, leaving the copy's old scene with missing scripts), and let the user run the menu item in the real
  project; never copy generated scenes/assets back (their GUIDs differ).
- Saving: three slots (Save/SaveSlots, SaveSystem), written as you go (every Rest, and whenever something that lasts
  changes). Only a game begun from the title screen saves: pressing Play on Main in the editor keeps nothing. A new
  system that should last across quitting adds its piece to SaveData, SaveSystem.Capture and Apply (and a test).
- Pathfinding: `NavMeshBaker` (in every scene, via FinishScene) builds the Soured's ways from the scene's colliders
  when it loads, for slim and broad Soured; nothing is baked into the scenes. So environment meshes are imported
  readable (ModelImportRules); a stair or gap a Laden should use must leave it room (about 1.3 m clear).
- UI is built in code (`Scripts/Runtime/UI`: Hud, Banner, DeathScreen, UiKit with procedurally drawn sprites);
  no combat text: feedback lives in the world. Screenshots with the UI: `PlayCaptureTests.Capture_Ui`.
- UI reads gameplay state in LateUpdate. In PlayMode tests a coroutine resumes after Update but before
  LateUpdate, so wait one extra frame before asserting on the HUD (WaitForEndOfFrame doesn't run in batch mode).
- Unity logs from the CLI end up in `builds/unity-<command>.log`.
- Tuning lives on the components (Apprentice, Laden) with the brief's "Middle" values as defaults.
- Version control: git + LFS. Binaries (.blend, .fbx, images, audio, fonts) go through LFS via
  `.gitattributes`; add new binary extensions there before committing them.
